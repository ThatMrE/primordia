# 02. Selected grants on the website, straight from Airtable

Status: draft for critique. Estimate: 3 days. Depends on 01 for the deploy hook secret.

## Outcome

When the panel approves a grant and ticks "Publish", the grant appears on `/grants` within minutes. Nobody edits HTML. `content/projects.json` stops being hand-maintained.

## Airtable: one new base, "Primordia Grants"

Owned by the organization, not a personal account. Tables:

| Table | Purpose | Key fields |
|---|---|---|
| Applications | Every submission, one row each | the ten questions, Name, Email, Country, Submitted, Decision, Review Note, AI Score, AI Summary, AI Strengths, AI Concerns, Cycle |
| Grants | One row per funded project. Created from an approved application by automation | Title, Slug, Grantee (public name), Field, Location, Amount, Summary (public), Image, Status (Funded, In progress, Reported, Published), Cycle, Funded on, Publish (checkbox), Application (link), Updates (link) |
| Updates | Monthly grantee updates (see 03) | Grant (link), Month, What happened, What changed, Photo, Spend to date, Link, Publish |
| Cycles | One row per monthly cycle | Month, Opened, Closed, Decided on, Paid on, Applications, Funded, Pool |
| Donations | Money in (see 05) | Date, Source, Amount, Currency, Designated grant, Reference |

The review deck (PR #12) points at Applications. Its Decision write-back feeds the Grants automation.

## Sync, at build time

1. `scripts/sync-airtable.mjs` runs first in `npm run build`. It reads Grants where Publish is true, Updates where Publish is true, Cycles and Donations. It writes `content/grants.json`, `content/updates.json`, `content/cycles.json`, `content/ledger.json`. It downloads grant images into `images/grants/` with a content hash in the name.
2. The token is a read-only Airtable token in the Netlify build environment. Deploy previews use the staging base.
3. When Airtable is unreachable the build uses the JSON committed from the last successful sync, logs a warning, and still deploys. A grant never disappears because of an outage.
4. An Airtable automation on Grants and Updates ("when Publish becomes checked" and "when a published record changes") calls a Netlify build hook. Debounced to one build per five minutes by the automation script.

## Website

- `/grants`: all published grants, newest cycle first, with filters by cycle and field. Replaces the Cohort 01 showcase data source. The Cohort 01 page keeps its editorial text and reads its seven projects from the same JSON.
- `/grants/<slug>`: one page per grant with the public summary, amount, location, status, image, and the update timeline from 03.
- The homepage "Cohort 01 stats" block becomes "Grants to date" and reads counts and dollars from `cycles.json`.
- Pages are generated by the existing build (`scripts/build-static.mjs` plus a small page generator), so the smoke test covers them.

## Risks

- Airtable attachment URLs expire. The sync downloads images at build time, so the site never links to Airtable.
- A grantee's private answers must never reach the site. Only fields on the Grants table are public. Applications is never read by the sync.
